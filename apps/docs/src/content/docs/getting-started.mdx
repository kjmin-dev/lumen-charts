## Create your first chart

Give the container a height in CSS (`autoSize` is enabled by default and tracks the container's content box through a shared `ResizeObserver`). Framework wrappers manage mount, reactive `options` updates, and unmount cleanup while exposing the `ChartApi` for series, data, indicators, and live ticks:

<Tabs syncKey="framework">
<TabItem label="Vanilla">

```ts
import { createChart } from 'lumen-charts';

const container = document.getElementById('chart')!;
const chart = createChart(container, {
	theme: 'auto', // 'light', 'dark', or follow prefers-color-scheme
	accessibility: { label: 'BTC/USD 1-minute prices' },
});

const candles = chart.addSeries('candlestick', { id: 'BTCUSD' });

// Times are UTC milliseconds. Pass typed-array columns for long histories,
// or an array of { time, open, high, low, close, volume? } objects.
candles.setData({ time, open, high, low, close });
chart.timeScale().fitContent();

// Add indicators computed in the data engine.
candles.addIndicator('bollinger', { params: { period: 20, multiplier: 2 } });
candles.addIndicator('ema', { params: { period: 50 } });

// Stream ticks: updates the bar with the same time, or appends a new bar.
candles.update({
	time: Date.now(),
	open: 101.0,
	high: 102.0,
	low: 100.5,
	close: 101.4,
});
```

</TabItem>
<TabItem label="React">

```tsx
import type { OhlcColumns } from '@lumen-charts/core';
import { LumenChart, type ChartApi, type ChartOptions, type DeepPartial } from '@lumen-charts/react';
import { useEffect, useState } from 'react';

const options: DeepPartial<ChartOptions> = {
	theme: 'auto', // 'light', 'dark', or follow prefers-color-scheme
	accessibility: { label: 'BTC/USD 1-minute prices' },
};

export function FirstChart({ bars }: { bars: OhlcColumns }) {
	// Passing setChart as the ref runs effects as soon as the chart mounts (and under StrictMode).
	const [chart, setChart] = useState<ChartApi | null>(null);

	useEffect(() => {
		if (chart === null) return;
		const candles = chart.addSeries('candlestick', { id: 'BTCUSD' });
		candles.setData(bars);
		chart.timeScale().fitContent();

		// Add indicators computed in the data engine.
		candles.addIndicator('bollinger', { params: { period: 20, multiplier: 2 } });
		candles.addIndicator('ema', { params: { period: 50 } });

		// Stream ticks: updates the bar with the same time, or appends a new bar.
		candles.update({
			time: Date.now(),
			open: 101.0,
			high: 102.0,
			low: 100.5,
			close: 101.4,
		});

		return () => chart.removeSeries(candles);
	}, [chart, bars]);

	return <LumenChart ref={setChart} options={options} style={{ height: 420 }} />;
}
```

## Columnar vs. object input

Both columnar typed arrays and arrays of bar objects work with `setData` and `prepend`:

- **Columnar (`OhlcColumns` / `LineColumns`)**: `{ time: Float64Array, open: Float64Array, high: Float64Array, low: Float64Array, close: Float64Array, volume?: Float64Array }`. Fastest path for large histories — avoids allocating millions of objects and transfers cleanly to the worker.
- **Objects (`OhlcBar[]` / `LinePoint[]`)**: `[{ time, open, high, low, close }, ...]`. Convenient for small datasets and JSON API payloads.

Times must be UTC milliseconds in strictly increasing order.

## Asynchronous engine & workers

History lives in the data engine (`@lumen-charts/engine`), which runs in a Web Worker by default. Data calls return immediately and apply asynchronously:

```ts
candles.setData(history);
await chart.whenIdle(); // resolves once everything handed over so far is painted
```

If the page's Content Security Policy blocks workers, Lumen Charts automatically falls back to running the engine on the main thread in short time slices behind the exact same API. To force main-thread mode or supply an explicit worker factory for your bundler, pass `worker` in `options`:

<Tabs syncKey="framework">
<TabItem label="Vanilla">

```ts
import { createChart } from 'lumen-charts';

// Force main-thread time-sliced mode (no worker):
const localChart = createChart(container, { worker: false });

// Supply the worker explicitly when a bundler requires worker creation in app code:
const createEngineWorker = () =>
	new Worker(new URL('@lumen-charts/engine/worker', import.meta.url), { type: 'module' });
const bundledChart = createChart(container, { worker: createEngineWorker });
```

</TabItem>
<TabItem label="React">

```tsx
import { LumenChart, type ChartOptions, type DeepPartial } from '@lumen-charts/react';

// Define the worker factory once at module scope so charts share the worker pool.
const createEngineWorker = () =>
	new Worker(new URL('@lumen-charts/engine/worker', import.meta.url), { type: 'module' });

const workerOptions: DeepPartial<ChartOptions> = { worker: createEngineWorker };
const localOptions: DeepPartial<ChartOptions> = { worker: false };

export function BundledChart({ useWorker = true }: { useWorker?: boolean }) {
	return <LumenChart options={useWorker ? workerOptions : localOptions} style={{ height: 420 }} />;
}
```

## Clean up

Call `chart.destroy()` when removing a vanilla chart from the DOM so its canvases, observers, event listeners, and engine slot are released. The React, Vue 3, Svelte 5, and Solid bindings call `destroy()` automatically on unmount — you only need to clean up external streams (such as WebSockets) or subscriptions you attach yourself.
